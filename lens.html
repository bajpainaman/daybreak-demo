    Find, fix, prove
    
        
    Try the model's suggestions, most natural first. Each one is run against emulator A, an independent implementation of the same spec. The first edit that passes every check wins.
    
        
    
        
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    Quick, good, cheap
    
      
    Training is counting: every token after every short run of tokens, across the whole codebase.
    
      
    A suggestion is only a guess until a check agrees.
    
    
    
    
    
      
    Where it stops
    
      
    The model learns habits, and habits are not intentions. Correct code that is merely unusual looks suspicious, and a bug that follows a common pattern looks normal. It can only propose one-token edits, so bugs that need a missing line or two lines swapped are flagged, not fixed. Nothing it suggests is applied without a check.
    
    
    
    
    
      
    Where it goes
    
      
    The spec becomes the program. Daybreak's CPU was a spec this morning; independent builders implemented it, and their cross-check is what made the code correct. Write the spec and the checks, and implementations become replaceable.
    
      
    CI becomes a lookup. The habits are indexed once. Every change is checked against the index in milliseconds, and a fix is the index's best alternative, kept only if the checks pass.
